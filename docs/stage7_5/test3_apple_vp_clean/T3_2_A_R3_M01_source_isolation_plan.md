## 2. 第一候选 · 普通 P3 A 等长全零 → 固定居民

**唯一变量为素材的 PCM 内容。** 两轮分别以独立 App/Engine/RunID 进入普通 DEBUG Prepare A、RECORDING、AGC ON、VP 双端 ON、无额外预热。顺序在运行前冻结为全零后居民。两份素材均为 24 kHz 单声道 PCM16LE、114032 帧（约 4.751333 秒），每轮用同一输出路径排程一次。有声臂使用已登记的原 HOST_resident.wav。全零臂另行批准后在本机制作同格式、同帧数纯零样本，冻结哈希并检验完整 WAV；原素材只读。全零臂保持系统输出 55%、未静音，保留原 Player、输出路由和确认面板。

源码表明普通 A 从原文件入口按格式、非空数据段和大小接收 PCM，并经原 enqueue／start 路径播放。它的当前 Fail-Fast 资格按普通 A、RECORDING、AGC ON 及身份绑定判定。全零素材的实际排程、路由及证据资格须在下一次获批执行中读回；当前仅为代码入口资格。原自动控制若只接受居民文件身份，保留原本的拒绝行为，使用获批且可核验的原界面人工选择和确认流程，无法安全核验则阻塞。 [文件读取与模式资格](../../../apps/macos/Aftelle/AppController.swift#L8143) · [排程](../../../apps/macos/Aftelle/AppController.swift#L8302) · [P3 Fail-Fast 绑定](../../../apps/macos/Aftelle/AppController.swift#L8396)

| 比较结果 | 预期判断与验收边界 |
|---|---|
| 有声臂复现原条件下的候选，合格全零臂亦有相近能量、时长、谱形的瞬态 | 类似瞬态可在无居民节目时出现。对该全零观察排除本轮居民语音，降低仅以声学回灌解释共同现象的优先级。两轮事件是否同源仍待证据 |
| 有声臂复现且满足原短窗疑似条件，全零臂对应区间无相近事件 | 支持居民节目参与。素材的非零内容同时改变空气声和 VP／输出链的输入，A 与节目触发的 B/C 仍可相容 |
| 正向未复现或配对不可比 | 分别登记 NOT_REPRODUCED 或 INCONCLUSIVE，按原次数上限结束 |

全零臂须有素材哈希匹配、一次原 Player.play／完成、有效 Render 观察且无非零节目帧，并登记用户实际听闻。扬声器电声链仍通电，可能产生瞬态。若无可信的零臂对应位置，使用预登记的 WAV 0–2 秒与 8–10 秒同长度窗口描述早段与稳定段，并检查实际覆盖和事件阶段。对应时点无法核验时，配对归属为 INCONCLUSIVE。全零参考保持无有效方差。

**预算和授权。** 最多两次 Capture，各 ≤15 秒、720000 bytes，一次全零排程和一次固定居民有声播放，合计计划采集 ≤30 秒。主控另行批准后，用户明确授权这两次实际采集、两种输出排程、两臂本机导出及离线分析；全部通过原 App 同意与每轮来源核验。主要风险为真实环境录入、CLOCK 截断及跨独立启动的偶然变化。预期增益是取得此前欠缺的同配置节目有／无对照，本轮无需新采集。

## 3. A · 只改变扬声器到 TinyUSB 的空气声路

两轮都播放同一份原素材，各一次。**唯一变量为固定摆位下的被动声路衰减**。同一扬声器、麦克风、线缆、增益、路由、VP/AGC、首个播放排程及格式，保持位置、朝向、桌面接触和人员状态。未来只在已有、经批准的被动隔挡能在设备启动前静态放置，且经合格独立参照证明 TinyUSB 附近的居民声场可比较且确实衰减时准入。实际 Playback/WAV 时序与两路素材一致性、参照身份及对齐误差一并核验。当前登记装备缺少合格独立参照，M29 原路线维持现有裁定。 [M29 资格与停止条件](T3_2_A_R5_M29_acoustic_reference_feasibility.md#8-缺失条件裁定及唯一下一步)

- 合格时若近端实测节目能量降低，相关的起音分量也随之降低而程序、Render 和事件时序保持，支持 A 的物理声路贡献，降低纯启动瞬态或独立背景声解释的优先级。若近端居民声场确实衰减而起音能量及其居民模板分量仍相近，降低直接空气回灌解释的优先级，保留 B/C。被动隔挡会改变房间反射，VP 也可能因声场改变而调整。
- 验收须证明衰减真实发生，参照及 WAV 均覆盖候选，且已匹配原有声短窗证据。若两臂仅有听闻或软件 Render，物理衰减资格保持 UNVERIFIED，停止来源判定。
- 预算上限两次、各 ≤15 秒，各一次固定居民播放。用户需另行授权放置隔挡、麦克风与真实外放、同步独立参照的采集与本机存储和分析。任一设备或保护边界不满足即停止。本阶段不添购设备、不建立新采集链。

## 4. B · 移动有声起点，保持 Engine／Player 首次启动方式

先用合格全零臂已登记的起始和稳定窗口观察事件是否聚集在生命周期边界，新增 Capture 为 0。仍需判别时，拟用两份等长素材做普通 A 对照。将同一原 PCM 全段在一份末尾附加 0.5 秒零样本、在另一份开头附加同样零样本。两份均为 126032 帧，同一居民内容、电平和首个 Player 启动控制。**唯一变量为居民内容相对该次排程的起点**。未来生成和核验两份独立哈希需另批，原素材保持只读。

- 预先冻结相对生命周期锚及节目锚的比较窗口，两套预测经实际误差界验证可分开。验收须证实两臂各一次 Player.play，同一原路径、格式及控制，实测非零 Render 的移动与规定的 0.5 秒一致且无中间重建。两种时间轴资格有缺项时为 INCONCLUSIVE。
- 若短事件仍贴近一致的 Engine／Player 状态边界，有声起点则后移，支持启动／输出链类解释。若晚臂事件经合格证据确定先于居民节目，排除晚臂该事件的本次居民语音回灌。USB 或扬声器电路启动仍可相容。若瞬态跟随非零节目起点，则降低单纯启动边界解释的优先级，保留空气声和节目触发的内部状态变化。
- 预算上限两次、各 ≤15 秒，合计两次有声播放。用户另行授权本机生成两份移位素材、两轮采集和输出、导出和离线分析。条件风险是不同静默长短也可能改变 VP 的实际状态。信息增益是区分事件跟随启动边界还是跟随节目，而无需在当前普通 A 中引入延时排程控制。普通 P3 A 的现有门控保持独立，移位条件通过等长 PCM 实现。 [DEBUG 启动资格](../../../apps/macos/Aftelle/AppController.swift#L8081)

## 5. C · 只改变有具体证据指向的一项外部因素

先查既有路由、格式、时间与连续性记录；用户已指出的外部声源或既有设备记录才作为对照选项。择一，冻结后两轮均使用同一全零素材及普通 P3 A，副作用和资格缺口留档。

| 候选唯一变量 | 固定条件与验收 | 可支持的判断 |
|---|---|---|
| 已识别、可安全静停的独立环境声源存在／静停 | 人员、房间、设备摆位、路由和 VP 状态相同。记录该声源的真实状态及可核验事件时间，确认两轮均无居民节目 | 瞬态随该已见证环境源出现或消失，支持 C 的环境来源，降低纯 VP 启动解释。无法实证声源变化时保持 UNKNOWN |
| 有定点日志支持且已验证合规的同一 TinyUSB 直连接口 | 只改一个现有 USB 连接位置，同一设备、线缆、声学位置、输出、增益与 VP 配置；重新枚举导致的预期标识差异须预登记。比较前核实两臂均稳定、无运行中路由或配置异常；无法验证则停止 | 仅某一连接条件出现候选，支持 USB／链路相关的条件差异。重新枚举可能影响 VP 状态，芯片或算法根因仍待证据 |

每项候选最多两次、各 ≤15 秒、全零排程各一次。需单独授权该唯一外部变化、两次实际麦克风采集和输出排程、JSON/WAV 本机保存及限定分析。没有已识别的可控外部因素时停在既有记录审查。一个环境对照只能覆盖指定声源，一轮无事件的证据强度有限。

## 6. 共同准入、时间语义与停止规则

1. **配置和身份。** 未来冻结源码、launcher／dylib、原界面及预计素材 SHA，核验每轮实载身份、唯一 PID／RunID、Capture/Playback Generation 和 ConfigurationID。保持已登记 TinyUSB 60%、Mac mini 内置扬声器 55%、未静音，VP 双端 ON、AGC ON、bypass 与 inputMuted 为 false，两运行点核验实际设备、格式与 active Mic Mode。原 P3 记录 active/preferred 为 0，保留两者各自语义。不同轮次各自的身份须与其快照绑定。保留每轮 15 秒／720000 bytes 的原采集计划上限、用户静默、每臂实际听闻和原可见 Stop。
2. **证据资格。** 预先登记分析窗和可比标准，包括 PCM 真实覆盖、20 毫秒包序列、时钟与观测连续性、运行态、SHA、Player 与 Engine 事件、一个实际播放完成及资源释放。沿用原 5 毫秒 RMS、相同静窗 P95 与起音局部峰值门槛，以及 20／40／80 毫秒稳健 NCC 与反向／错时／静窗判据。有声稳健搜索按真实非零 Render，确保完整时段在有效 PCM 内。Native 指 VP 后观测，Player Tap 指数字 Render。生命周期调用和回调到达在其自身时间轴核对，WAV/Render 内容时间另核对。缺乏经证据验证的映射时，对需要跨轴的结论保留 UNKNOWN。软件偏移与声学传播不作等同解释。 [事件和时间语义](T3_2_A_D2_R3_M01_debug_timing_observation.md#2-观测字段来源与时间语义)
3. **CLOCK 或安全异常。** 当前普通 A Fail-Fast 的同 Run、代际、配置和内容时钟确认合同原样适用。若 App 已因 CLOCK 进入停止流程，等待该流程封存。若观察到其他 CLOCK／路由／时序、身份、权限异常或用户取消，按原 Stop 停止当前轮，剩余轮次全部取消。记录首条故障、原时钟诊断、事件与封存身份，原导出界面只导出允许保留的有效连续前缀及 JSON，收尾后核验精确 PID 退出、Engine 和设备释放。部分覆盖保留实际边界和未知项。触发门槛与拒收规则保持。 [Fail-Fast 与证据保留合同](T3_2_A_P3_clock_fail_fast_review.md)
4. **授权与隐私。** 每个对照须有独立主控批准和用户明确同意，范围绑定 App/设备、实际有声或零输出、录音时间、动作与次数、原界面确认、本机保存／导出以及可分析的文件与区间。历史设备许可和历史原件读取许可按原用途登记。遵守现有系统麦克风权限，新的系统许可或不合规状态触发停止。证据目录 0700、文件 0600，UID、原始日志、WAV、PCM、原始 JSON 仅留本机，远端仅含脱敏结论、必要数值与哈希。
