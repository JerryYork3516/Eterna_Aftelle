# Native Voice · 本地双讲实验报告 · 2026-11-27

## 结论

完成一次 15 秒实机双讲。用户确认听见居民声音时仍在讲话，并反馈居民声出现时真人音量被压低，同时还能听到少量居民声音。本轮双讲的两项听感问题仍然存在。近端衰减量、居民残余能量和根因尚待测定。

## 实验方法

- 使用独立签名 Debug 实验窗口的「双讲（WAV）」模式。居民声源由同一个 Native Voice 音频图的 SourceNode 送入 Apple Voice Processing，采集为 Apple VP 处理后的麦克风信号。真人提供近端语音，Qwen 不参与。
- 设备预检读回默认输入为 TinyUSB DFU runtime，默认输出为 Mac mini 内置扬声器。输入音量 60.49%，输出音量 59.86%，两端均未静音。使用原有设备设置。
- 读回 Apple VP 输入和输出均启用，AGC 开启，bypass 关闭。协商格式为 Sink 和输出 16 kHz 三声道、Source 16 kHz 单声道，均为非交错 Float32。导出麦克风 WAV 为 24 kHz 单声道 PCM16LE。
- 使用原幅固定居民 WAV `HOST_resident.wav`，约 4.751 秒，首 1.000 秒为原文件静音。参考文件 SHA-256 为 `774e450ce1ff92402051f89ae4fcd537d74367deff9c2f92670ba0f6637d47ea`。
- 以程序记录的「现在讲话」提示为时间零点。窗口提示用户开口并持续到停止提示。程序在第 3 秒向音频图送入原幅 WAV，第 15 秒结束采集。真人实际开口时点未由独立参考测量。

## 实验过程

| 相对讲话提示 | 实际读回 |
| ---: | --- |
| 0.000000 秒 | 窗口进入讲话阶段并启动 15 秒计时 |
| 3.006674 秒 | Transport 接受原幅 WAV 的首块 PCM |
| 4.049461 秒 | Source 首次报告含非零帧的回调 |
| 7.764372 秒 | 程序观察到 Source 确认数字结束 |
| 15.178249 秒 | 音频图确认关闭，播放及麦克风采集停止 |

用户确认在居民实际发声期间仍在讲话。窗口在停止后本机导出 `capture.wav` 和 `manifest.json`。封存检查通过，WAV 格式、时长及摘要与 JSON 一致。两份证据留存在本机私有缓存。
