# T3.2-A · Step 4-B 音频归因与 A/B 对照

## 1. 裁定

**居民有声条件下的额外近端男声衰减得到支持（`SUPPORTED`）。** 配对相同 Windows 源内容后，B 轮在播放前的男声投影 RMS 较 A 轮仅低 **0.38 dB**，播放窗内低 **7.84 dB**，NCC 中位数从 A 轮的 **0.916** 降到 B 轮的 **0.411**。改用 B 轮的 400 ms 窗格作为配对起点，窗内差异仍为 **−6.39 dB**。窗内部分明确有声的源片段在 B 轮近乎失配，其他片段仍可可靠匹配。该结果支持有声播放条件与衰减相关，尚无法识别 AGC、Apple VP 内部处理或实际声场的具体贡献。

B 轮居民模板在共同偏移处未稳定超过反向负控。居民残留及其能量保留 `UNKNOWN`。本轮只覆盖外部男声波形和固定居民模板的离线归因。

## 3. 对齐、FIR 及负控

- 沿用 8 kHz、150–3400 Hz 零相位带通，逐窗中心化 NCC，26 个 640 ms 搜索窗和五档 ±2000 ppm 循环搜索。固定同一数字映射并用各段窗口交叉验证。A 的录音零点映射到源 **4.51825 秒**，B 映射到 **5.119125 秒**，两者相差 **4807 个 8 kHz 分析样本**，即 B 在录音零点的素材进度领先约 **0.601 秒**。这是数字内容相位。播放器真实起播时刻、传播延迟及麦克风处声压均未知。
- 沿用外段交替 400 ms 窗训练 / 留出、161 系数、约 ±10 ms 的正则化 FIR、参考 RMS ≥0.004（约 −48 dBFS）和逐窗非负功率投影。0 ppm 留出 NCC 中位数在 A/B 分别为 **0.895 / 0.935**，B 的 −10/+10 ppm 对照为 **0.926/0.896**，保留原 0 ppm 模型。交换训练和留出窗，B 窗中 NCC 仍为 **0.637–0.655**，投影 RMS 相对窗前留出下降 **10.85–12.64 dB**。
- 走原正向、反向、错时、静窗负控。固定相位 ±1、±2、+5 秒错时的各段绝对 NCC 中位数上限分别为 A **0.086**、B **0.057**。全长反向或错时个别窗会有高峰，稳定对齐依赖共同相位及留出匹配。原合成循环接缝、510 ppm 速率偏差、静窗、反相及混合检验通过，已知 −15 dB 恢复为 −14.936 dB。本次未调整检测阈值及波形度量。 [历史对齐和负控](T3_2_A_step4_external_source_doubletalk_attribution.md#3-数字对齐和对照)

## 5. B 轮居民模板残留

沿用固定居民素材首 1 秒静默后的模板、六个 500 ms 分窗及 ±250 ms 数字偏移网格，以 B 实际非零 Render 为软件锚点。对原录音以及扣除可匹配男声投影后的残差，分别搜索正向和反向模板共同偏移处的跨窗中位绝对 NCC。

| 历史有声轮原录音 | 0.0582 | 0.0772 |
| 历史有声轮残差 | 0.0587 | 0.0587 |

B 各窗的最优偏移未收敛。原短窗边缘复核首次两个相邻窗的正向峰为 **+0.326** 与 **−0.252**，最优数字偏移相差约 313 ms。两次有声运行均未取得稳定、超过负控的居民模板证据。弱残留、非常短的渗漏或非线性形变仍可能避开此方法，独立居民回声能量为 `UNKNOWN`。 [历史有声居民模板口径](T3_2_A_step4_external_source_doubletalk_attribution.md#5-居民模板与证据等级)

## 6. 解释边界与唯一后续实验

| 判断 | 等级 | 边界 |
| --- | --- | --- |
| 有声 B 轮的可匹配男声在播放窗内额外下降 | CONFIRMED_OBSERVATION | 同源配对及两套窗格均出现，窗前基线接近，窗后匹配恢复。 |
| 居民有声条件与额外近端衰减相关 | SUPPORTED | A/B 一对运行及历史有声轮方向一致。播放是唯一计划改变的变量，但无法排除实际声场、设备状态及运行历史的差别。 |
| AGC 增益参与程度 | UNKNOWN | 两轮公开配置均 ON，缺少运行中处理增益和内部状态读回。 |
| Apple VP 双讲处理及 AEC 内部参考 | UNKNOWN | 无 VP 前测量及内部参考观测。Player Tap 与 VP 后 Native 分别只覆盖软件路径的两个位置。 |
| 声学耦合及物理重叠 | UNKNOWN | 两个声源的麦克风处声压、实际重叠时长和实际传播时延未独立测量。 |

**优先只验证 AGC 配置这个变量。** 复用已存在的 DEBUG「Original C · no warm-up comparison」综合 C，固定居民有声素材，做 AGC ON / OFF 一对。在同冻结候选上预先固定启动顺序、Windows 播放方式和源相位、两声源摆位、音量、居民时序、Capture 和停机规则；以实际读回证实 VP 双端和 AGC 目标状态。分析优先采用相同源内容有声窗，并保留前段与窗后负对照。若 OFF 下深度失配显著缓解而前段资格维持，支持效果依赖 AGC 配置。若两臂均同样失配，则降低 AGC 设置单独解释的优先级。处理模块内部耦合仍需独立证据。任何 CLOCK、路由、源内容配对或有效覆盖失败均记为不合格，无自动恢复。该方案需要另行批准；本轮没有依据修改生产处理。 [现有 DEBUG 配置入口](../../../apps/macos/Aftelle/ContentView.swift#L837) · [综合 C 配置判定](../../../apps/macos/Aftelle/AppController.swift#L7957)
