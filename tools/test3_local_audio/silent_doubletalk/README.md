# Test 3 静默双讲回归

在 Apple Silicon macOS（Xcode、仓库已有 WebRTC XCFramework）运行：

```sh
tools/test3_local_audio/silent_doubletalk/run.sh
```

每次从当前生产 Bridge、`MacSpeechWebRTCAECProcessor` 和 Host 编译，复用
`tools/webrtc_aec3/offline_aec_validation.cc` 的确定性公开合成方法。
无需 Python、旧 `.build` 输入、录音、扬声器、麦克风、Qwen、凭据或网络。

原四组各 20 秒：正常/2x 远端纯回声，以及正常/2x 远端同时叠加独立近端。
远端物理回声路径为 120 ms，Bridge 缓冲延迟 3 ms；前 12 秒只有回声，
正对照后 8 秒加入合成近端。近端不进入 render 参考。四组完整运行，
不会因为 Host 开门而截断后续合成信号。

Test 3 / 01新增三组完整输入/停说检查：正常、2x外放模拟和隔离输入模拟。
近端从12秒开始，使用十个完整580ms音节周期，到17.8秒已结束；居民继续到20秒。
隔离组raw严格等于near，render仍在播放，不能按耳机/麦克风名称直接放行。
这只是隔离声路模拟，不是任何真实耳机或外置麦克风组合的硬件证明。

新增三组的正确预期由生成的near源定义，不从Host旧输出取标签：

- 所有已知有效近端帧在现有AEC3处理延迟432个48k样本对齐后，完整通过Gate；
  记录每个缺失帧，不能用“至少放行一点”或总量达到500帧代替。
- 不重复发出源帧；断言检查首段、内部和尾段，不能只看首次开门。
- 从源最后非零样本加已知AEC延迟起，沿用20个10ms帧的弱证据预算；
  到期后不得继续放行或被纯回声再次开门。该判据不是语义VAD超时。

Gate覆盖只证明声学路径没有截断相应源时间段；不会证明AEC后的音节可懂度、
文本完整或真实房间中的语音质量。原四组的较弱历史断言保留，但不能作为新增
完整性要求通过的替代。全部七组执行，任何一组失败总退出码非零。

负对照断言全程没有门控开启、非零放行或用户声学证据。正对照断言回声
预热期不放行；后 8 秒远端持续有声，至少 500 个已知近端有声帧与远端
同时有声并获放行。分析标签来自生成信号的 RMS（近端 ≥0.006、远端
≥0.005），不是分类结果，也不改变生产门槛。

证据保留在 `.build/test3-local-automation/silent-doubletalk/run.*/`，包含
`result.json`、合成输入、当前二进制和编译前后源码 SHA。七组全部执行，
任一断言失败返回非零退出码。帧号从 0 开始，每帧 10 ms；首次实际发出
与 pre-roll 源帧分别记录。近端首次起点在第 1200 帧，随后合成音节有
150 ms 间隙，不应隐去这段延迟。

这是实际 WebRTC 与 Host 的确定性信号回归；不覆盖真实声场、设备路由、
Runtime 中断决策或真实 Qwen 语义，不能单独宣告实机 Test 3 通过。
